# CV Standard

## Target

Primary audience: software engineering recruiters, engineering managers, technical leads, and hiring systems.

## Canonical format

- PDF for distribution.
- One-column layout.
- 1–2 pages depending on experience.
- White/light neutral background.
- Dark text.
- One restrained accent colour.
- Accessible typography.
- No skill bars, star ratings, progress circles, or decorative charts.
- No photo by default.
- Links should be readable and functional.
- Dates should use one consistent format.

## Content order

1. Name and professional headline
2. Contact / professional links
3. Professional summary
4. Experience
5. Selected projects
6. Technical skills
7. Education
8. Certifications / additional information when relevant

## Experience entry

Each role should contain:

- company
- title
- location when useful
- dates
- 2–5 bullets for recent/high-value roles
- fewer bullets for older/less relevant roles

Bullets should generally follow:

**Action + technical context + outcome**

Example:
"Designed a modular .NET service architecture for user and file-management workflows, improving separation of concerns and simplifying future feature development."

## Summary

The summary should be 3–4 lines and should answer:

- What kind of engineer is this?
- What technical areas are strongest?
- What type of problems does the engineer solve?
- What seniority/ownership level is demonstrated?

## Skills

Group technologies by meaningful engineering domain, for example:

- Languages
- Backend
- Frontend
- Mobile
- Databases
- Cloud / DevOps
- Architecture / Practices
- AI / Data

Do not assign percentages or proficiency scores.

## Links

Use stable professional links only. Validate URLs before publishing.

## Public website

The website is a presentation layer, not a second CV database. It may include richer project context, but facts must originate from Content/Career.
